# Beatham brand — core and sub-brands

Live guidelines: https://beatham.netlify.app (BeathamBase `main`). Roadmap and open decisions: `docs/BRAND_PHASES.md` in BeathamBase.

> **Managed by BeathamBase.** In a project, this file arrives with `npm run brand:sync`; edit it in BeathamBase, not here.

The Beatham core brand is the system every Jeremiah Beatham product inherits — apps, sites, watch apps and 3D-printed objects. It was set for HandCAD on 2026-10-03 (Jeremiah's 28 answers, HandCAD ADR-0012 "Instrument") and abstracted here: the **rules and the system** are core; anything that names one product's things is that product's **sub-brand**. Decision record: [ADR-0002](adr/0002-beatham-core-brand-and-subbrands.md). Distribution: [ADR-0003](adr/0003-brand-distribution-vendored-sync.md).

**Thesis:** *Precise, restrained, made by hand. Neutral carries the work; one warm amber marks what you touch.*

Guidelines site: `brand/site` (`npm run brand:site`), deployed as its own Netlify site (base directory `brand/site`).

## 2. The core rules

Every rule applies to the core **and every sub-brand**, and every rule that can be checked is (`brand:check`).

### Colour
- **Ramps are OKLCH, 9 steps, lightness-matched to the neutrals** — each step's L equals the Beatham neutral with the same number, so a gap of **40 / 50 / 60 steps gives ≥ 3 / 4.5 / 7:1**. Generated by `palettes.mjs`; a sub-brand's own ramp is held to the same rule. *(palettes)*
- **Jeremiah's colours are anchors.** Neutral 10–90 and the amber → brown brand ramp ship verbatim; Callout, Negative, Success, gold and the filaments are exact steps or mapped with a written reason; corrections ship beside originals (`brand/dist/core/ramps.json`, the site's Colour page). A sub-brand may not redefine a core ramp or palette. *(palettes, build)*
- **Contrast:** every pair in `contrast-pairs.json` (plus the sub-brand's) passes WCAG AA in every mode — 4.5:1 text, 3:1 graphics; high-contrast modes 7:1 / 4.5:1. Every semantic colour is paired or exempt with a reason. *(contrast)*
- **Colour never carries meaning alone:** a glyph and a label every time. *(review; do / don't)*
- **Hue budget:** at most **3** non-neutral, non-accent hues in the chrome (by default callout = info, negative = broken / caution, success = passed). Any other hue reaches a role only through a **grant** with a scope (`analysis`, `data`, `category`, `physical`, `mark`, or `chrome`) and a reason, and appears with a legend or label. *(roles)*
- **The accent rule:** the accent (default `brand` amber; `neutral`, or another core ramp through an accent grant with a reason, as Confident's teal) marks only what you act on — selection, focus, the active control. The accent ramp fills only `accent.*` / `selection.*`; those roles take only the accent or neutral. Links, headings, logos and the primary button are neutral. *(roles)*
- **User content is not brand colour.** Colour a person picks for their own work (strokes on a canvas, a drawing, a photo) is content: it is not a role, a ramp or a swatch set, and it is outside the hue budget. Let the system colour picker supply the spectrum rather than shipping a palette; the brand supplies only neutrals and, where the accent rule allows, the accent. *(review)*
- **Never in a role:** gold, brown and every palette (palettes are colour only). *(roles)*
- **Proportion:** every sub-brand declares a coverage system that sums to 100. Core default **90 / 7 / 3** — neutral / accent / signals. *(build)*
- **Modes:** dark is the reference (dark-first); every role has a light value; high contrast for both; **true black** (`neutral/100`) for dark bases and canvases. *(build)*

### Type
SF Pro for text (SF Compact on watchOS) · **Instrument Sans for titles only** (no ± or µ, so titles never carry values) · **JetBrains Mono for every number** (dotted zero, tabular; `calt` off in expression fields) · **Bitcount Single** for one hero numeral per screen at most · Apple Dynamic Type steps · bundled faces are OFL 1.1 with their licences in `brand/fonts/`, credited in each product.

### Atoms (2026-10-09)
Beyond colour, space, radius, type families, motion and haptics, the core defines: **opacity** (8 / 16 / 24 / 40 / 64, shown as alpha shades on the Colour page); **leading** (1.2 / 1.4 / 1.5) and **tracking** (−0.5 / −0.2 / 0 / +0.5 px) for text outside the type styles; **icon** sizes 16 / 24 / 40 / 80 and strokes 1.5 / 2; the **focus ring** (2 pt wide, 2 pt offset, `accent.focus`); web-only **breakpoints** (480 / 768 / 1024 / 1280), **columns** (4 / 8 / 12, max 1120) and **layers** (0–50). Each is a token in `brand/tokens/core/atoms.json` (and `font.leading` / `font.tracking` in `type.json`) shown on its own page. Opacity, icon, focus have Swift forms; breakpoint, grid, layer and mark are web / print only.

### Identity
Every brand, the core and each sub-brand, has four identity slots in its manifest (`identity.wordmark`, `icon`, `logo`, `rules`), each `not-defined`, `provisional` or `defined`, shown on the Identity page and enforced by the build. No mark is drawn yet; the `mark.*` tokens are provisional geometry (minimum sizes, clear space) until one exists.

### Layout and shape
8 pt between components, 4 pt within (2 and 12 only inside a component) · compact everywhere · **44 pt minimum targets** (12 pt hit halo for small marks) · radii **4 / 8 / 12** (capsule only for the system switch), concentric · **nothing clipped by a corner** (12 pt safe margin on the watch; 3 mm on a printed part) · flat: two layers, hairlines not shadows.

### Character
Voice **precise** (name the thing, the number and the fix) · minimalism **restrained** · motion **crisp** (100–250 ms, 350 ms camera, no overshoot, reduced-motion variant for every duration) · haptics are a token set (iOS generators, watchOS `WKHapticType`) and never the only feedback · icons are SF Symbols plus custom symbols on Apple's templates · illustration is technical line drawings.

### Pipeline
Tokens are the only source of visual values. Generated files are never hand-edited. `brand:check` fails on stale output, contrast misses, hue-budget or accent violations, and hard-coded colours / px / font stacks / shadows in `src/` and `brand/site/src/`.

## 3. Roles

| Group | Roles | Rule |
|---|---|---|
| `surface` | base, canvas, raised, control, scrim | dark: 100 → 100 → 90 → 80; light: paper 10 → white |
| `text` | primary, secondary, tertiary, disabled | AA on every surface |
| `border` | subtle (decorative), strong (3:1) | |
| `accent` | fill, fill-pressed, on, text, focus | the accent rule |
| `action` | primary-fill/-label (neutral), secondary-fill/-label, destructive-label | primary is neutral/20 + neutral/80 in dark |
| `selection` | stroke, fill (24 % tint), hover | the accent rule |
| `signal` | info (blue), negative (red), caution (light red), positive (green — results only) | with a glyph and a label |
| `feedback` | error / warning / success / info (+ `-surface`) | success and info neutral; banners flat |

Plus type (`type.*` on Dynamic Type), layout (`layout.*`, `radius.*`, `elevation.*`, `material.*`), motion (`motion.sheet / selection / snap / toast / camera`), haptics (`feedback-haptic.snap / confirm / complete / reached / warning / error / selection-changed`) and physical sizes (`physical.*`, mm).

## 4. Sub-brands

A sub-brand is a folder `brand/subbrands/<name>/` whose layers sit on top of the core. It may:

1. **choose palettes** — its accent ramp (`brand`, or `neutral` for no hue) and secondary / tertiary palettes from the library (or its own palette, colour only);
2. **remap core roles** within the rules — restating every mode where the core overrides that role (the build fails on a leak);
3. **declare its proportion system** (and alternates);
4. **add product roles** (new `color.<group>.*`, type styles, layout, motion, haptics) with **grants** for any hue they need;
5. **set platforms** — `web` (CSS), `ios` / `macos` / `watchos` (Swift), `print` (swatch export); JSON and `sheet.md` always.

It may not redefine core ramps or palettes, grant the accent ramp elsewhere, or put gold, brown or a palette in a role. All checks run per sub-brand.

### Layer order
core base layers → sub-brand `layers` → core mode layers → sub-brand `modes/<mode>.json`. A high-contrast mode takes the sub-brand's file for the mode it inherits first (light → light HC), so restate high-contrast values in `high-contrast-*.json` when the light value isn't strong enough. A role that only points at another role (`{color.signal.info}`) follows it through every mode and needs no light restatement.

### Adding a sub-brand
1. `mkdir -p brand/subbrands/<name>/{tokens,modes}` and write `subbrand.json` (copy a sibling). Required: `name`, `label`, `status` (`locked` or `proposal`), `thesis`, `platforms`, `palettes`, `proportion`, `do`, `dont`; a `proposal` must list `openQuestions`.
2. Add product roles in `tokens/*.json`, light / HC values in `modes/`, pairs in `contrast-pairs.json`, grants in `rules.grants` (each with `scope` and `reason`).
3. `npm run brand:build -- --subbrand <name>` and `npm run brand:check -- --subbrand <name>`; then a full `npm run brand:build` so the site picks it up.
4. In the product: `"beatham": { "subbrand": "<name>" }` in `package.json` (web), or add `brand/dist/<name>/Tokens.swift` to the Xcode target.

## 5. Outputs

| File | For |
|---|---|
| `brand/dist/<name>/tokens.css` | web: CSS custom properties `--<prefix>-*`, one block per mode on `[data-theme][data-contrast]`, OS-preference fallbacks, reduced motion |
| `brand/dist/<name>/Tokens.swift` | Apple: `<P>Tokens` (Foundation-only raw values), `Color.<p>…` (dynamic light / dark / Increase Contrast; dark on watchOS), `CGFloat`, `Font` (`Font.custom` with SF fallbacks, Bold Text), `Animation`, `Material`, `<P>Haptic` (UIKit / WatchKit). Type-checked with Swift 6 for iOS 17, macOS 14 and watchOS 10. |
| `brand/dist/<name>/tokens.json` | every token in every mode with CSS and Swift names, the manifest and check summary — the site reads it; usable for Figma variables |
| `brand/dist/<name>/sheet.md` | the brand sheet |
| `brand/dist/<name>/print/` | `swatches.json`, `.csv`, `.html` — hex, RGB, OKLCH, L\*a\*b\* (D50), provenance, spool fields, mixes, filament contrast matrix, physical sizes |
| `brand/dist/core/ramps.json` | every ramp's OKLCH analysis and how each of Jeremiah's colours was placed |

Prefix: `bt` / `BT` for everything, except `handcad`, which keeps `hc` / `HC` so HandCAD can adopt it without renaming.

## 6. Using it in a project

- **Web (this template):** `package.json` → `"beatham": { "subbrand": "core" }`. `vite.config.js` aliases `@brand` to `brand/dist/<sub-brand>`; `src/main.jsx` imports `@brand/tokens.css` and `brand/fonts/fonts.css`. Use `var(--bt-…)` in CSS and `token()` / `buildTheme()` / `setMode()` from `src/utils/theme.js`. The page follows the OS until `setMode` pins it.
- **Apple:** add `brand/dist/<sub-brand>/Tokens.swift` to the target (or a Swift package), bundle the fonts listed in `BTTokens.Fonts.bundledFiles` (see `brand/fonts/README.md`), use `Color.btSurfaceBase`, `Font.btBody`, `CGFloat.btSpace16`, `BTHaptic.confirm.play()`.
- **Physical:** open `brand/dist/<sub-brand>/print/swatches.html` and print it; fill in `brand/inputs/filaments.json` in BeathamBase as spools are identified.

## 7. Updates — `brand:sync`

Projects are copies of the template, so the brand is **vendored**: each project commits its own `brand/` and updates it from a tagged BeathamBase release ([ADR-0003](adr/0003-brand-distribution-vendored-sync.md)).

1. Change the brand **in BeathamBase only** (tokens, sub-brand, rules), `npm run brand:build && npm run brand:check`, merge, bump `brand/VERSION`, tag `brand-v<VERSION>` on `main` and push the tag (a person does this; steps in BeathamBase's `docs/RELEASING.md`).
2. In a project: `npm run brand:sync` (latest `brand-v*` tag) or `-- --ref brand-v1.2.0`; `npm install && npm run brand:check`; commit `brand/`, `docs/BRAND.md` and `package.json`.
3. `npm run brand:sync -- --check` reports drift (exit 1) — for repo-setup and CI. `brand/SOURCE.json` records the ref and commit a project is on.
4. A project that has no `brand/` yet (made before 1.0.0) gets it the same way: `node <BeathamBase>/brand/scripts/sync.mjs --subbrand <name>` from the project root (or `--from ../BeathamBase` offline).

Flags: `--no-site` (skip the guidelines site), `--no-docs`, `--force` (overwrite local edits), `--dry-run`, `--from <path or URL>`.

## 8. Moving HandCAD onto the core (plan — not done)

HandCAD owns its tokens today (`design/tokens`, `studio/scripts`, ADR-0009 / ADR-0012). The `handcad` sub-brand reproduces them: `node brand/scripts/compare.mjs ../HandCAD/studio/src/tokens.data.json --subbrand handcad` → **306 shared tokens × 4 modes, 0 values differ, nothing missing; 41 additions** (the `signal.*` roles, the filament ramps and palette, watch device widths, `physical.*`, the `confirm` / `complete` / `reached` haptics). Swift API: a strict superset of HandCAD's `Tokens.swift` (same names; new `hcSignal*`, `hcDeviceWatch*`, three haptic cases). The plan, for a HandCAD branch Jeremiah names:

1. **Sync:** in HandCAD, `node ../BeathamBase/brand/scripts/sync.mjs --subbrand handcad --no-site` (adds `brand/`, `docs/BRAND.md`, the `brand:*` scripts and the `style-dictionary` devDependency).
2. **Swift:** point the `HandCADDesign` target at `brand/dist/handcad/Tokens.swift` (or have the build copy it over `ios/HandCADKit/Sources/HandCADDesign/Tokens.swift`); the API is unchanged, so no call site moves. Fonts: `brand/fonts` holds the same six files with the same checksums.
3. **Studio:** import `../../brand/dist/handcad/tokens.css` instead of `studio/src/tokens.css` (same `--hc-*` names) and `brand/fonts/fonts.css`; read token data from `brand/dist/handcad/tokens.json` (same shape as `tokens.data.json`, plus `manifest` and `summary`) and ramp data from `brand/dist/core/ramps.json` (same shape as `ramps.data.json`).
4. **Checks:** replace the studio's `palettes:check`, `tokens:check`, `contrast`, `lint:roles` with `npm run brand:check -- --subbrand handcad`; keep `lint:values` for `studio/src` (or point `check-values.mjs` at it).
5. **Retire** `design/tokens`, `design/contrast-pairs.json`, `design/style-dictionary.config.js`, `design/inputs`, `design/fonts` and `studio/scripts` once 2–4 build green; keep `design/proposals` and `DECISIONS-2026-10-03.md` (the archive renders on its own frozen baseline, which needs `studio/scripts/lib` — keep a minimal copy or move the archive to read-only static data first).
6. **Record it:** a HandCAD ADR superseding ADR-0009's "tokens live in design/tokens" and pointing at BeathamBase ADR-0002; HandCAD's P2 then deletes `brand/subbrands/handcad/tokens/legacy.json` (space.20, radius.16 / 24, elevation.3) in BeathamBase.
7. **From then on**, HandCAD design changes are made in BeathamBase's `brand/subbrands/handcad/` and arrive by `brand:sync`.
